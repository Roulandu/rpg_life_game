## 2. 不可破坏的产品与技术约束

1. **引擎拥有事实**：比分、属性、合同、身价、赛程、伤病只能由确定性引擎产生；LLM 只写叙事和受约束的提案。
2. **确定性**：`src/engine` 与 `src/world` 禁止 `Math.random`、`Date.now`、`new Date()`、依赖 locale 的排序；随机数必须来自 `createRng(world.seed, domain, ...)`。
3. **本地优先**：无后端；存档在 IndexedDB；密钥只在本机（Web 会话级/可选加密，Android Keystore）。
4. **回退可玩**：无 Key、断网、超时、CORS、校验失败时必须回退模板事件，不能阻塞推进。
5. **化名数据**：真实国家/城市/联赛层级，俱乐部、球员、教练、球场全部化名，并做 denylist 相似度检查。
6. **纯文本渲染 LLM 输出**：不使用 `dangerouslySetInnerHTML`，不提供读取 URL/文件/密钥的工具。
7. **移动优先**：390×844 视口可用，触控目标 ≥44px，输入框 ≥16px，底部导航不遮挡内容。
8. **原子回合**：一次推进的所有状态变更统一提交，避免半更新存档。

## 3. 每个子项的工作流程

1. 从本文档认领子项，建立任务并标记 `in_progress`。
2. 先改领域类型与引擎，再改 store，最后改 UI。
3. 必写测试：happy path、边界、确定性/同种子回放；涉及存档时加往返测试。
4. 本地验证：
   ```bash
   npm run check
   npm run build
   npm run dev
   ```
   涉及 Android 时再跑 `npm run android:sync`。
5. 浏览器手动验收：新建/继续生涯 → 推进 → 关键流程 → 刷新恢复。
6. 更新本文档的复选框与状态表，提交并推送。
7. 子项完成定义（DoD）：测试通过 + 构建通过 + 手动验收 + 文档更新 + 无新增已知回归。
