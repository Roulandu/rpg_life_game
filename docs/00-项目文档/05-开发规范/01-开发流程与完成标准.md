# 开发流程与完成标准

本页是端到端流程索引；细则以各专题文档为准。

## 流程

1. **定位**：读 `docs/modules.yaml`，跑 `npm run quality:file -- <path>`，确认模块职责、契约、文档、测试与基线。
2. **建 CHG**：在 `docs/00-项目文档/08-变更与治理/01-变更记录/` 新建 `CHG-YYYYMMDD-NNN-中文标题.md`，写背景、验收条件、影响范围。
3. **RED**：先写失败测试并保留真实输出。
4. **GREEN**：最小实现让同一测试通过。
5. **REFACTOR**：行为不变的小步整理。
6. **DOCS**：更新功能文档/数据模型/契约；不涉及则 `Docs-Impact: none: <理由>`。
7. **CHECK**：`npm run verify -- --fast`；提交前 `npm run verify -- --full --base origin/main`。
8. **COMMIT**：六段中文模板 + RED/GREEN + `变更记录: CHG-...` + Trailer。
9. **CI**：push 后等待该 SHA 的 CI 结论；失败修复到绿。

## 完成标准（DoD）

- 行为有测试，RED/GREEN 真实且指向同一用例。
- CHG 状态与内容匹配（`draft` / `verified` / `accepted`）。
- 全量 verify 通过，报告已生成；无新增技术债、无测试数量下降。
- 文档与契约同步，或豁免理由充分。
- 存档变化有版本、迁移、fixture、往返测试与回滚说明。
- UI 在 360–390px 与桌面宽度手动验收。
- 提交信息完整；push 后 CI 绿；未推送时明确写“CI 待执行”。
