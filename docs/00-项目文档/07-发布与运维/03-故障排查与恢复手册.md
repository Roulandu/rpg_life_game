# 故障排查与恢复手册

按“先确认事实，再定位原因，最后修复并留下证据”的顺序处理。不要用删除数据、跳过检查或改写历史来消除症状。

## CI 失败

1. 定位本次 SHA 的运行：`gh run list --commit "$(git rev-parse HEAD)" --limit 1`。
2. 取失败日志：`gh run view <run-id> --log-failed`。
3. 在本地用同一命令复现，例如 `npm run verify -- --full --base origin/main`。
4. 修复后创建**新提交**并重新 push；已推送提交不 `--amend`。
5. 只有 runner/网络等基础设施问题才考虑重跑，且必须等到最终结果。

常见原因：

| 现象 | 排查 |
|---|---|
| `对比基线不可达` | 检查 `--base`、是否 `fetch-depth: 0`、PR 目标分支是否 fetch |
| 文档同步失败 | `npm run docs:build` 后提交生成文件；补功能文档或契约 |
| 测试影响失败 | 补模块测试；确需豁免时在提交写 `Test-Impact: none: <理由>` |
| 覆盖率下降 | 补测试；不得下调基线 |
| 变更记录失败 | 补 CHG/VER 或修状态与章节，见 [治理说明](../08-变更与治理/00-治理说明.md) |

## Git hooks 未生效

```bash
npm run hooks:doctor   # 检查 core.hooksPath 与钩子文件
npm run hooks:install  # 重新安装
```

钩子只是本地提前反馈；CI 仍会复查提交范围。不要因为钩子未装就认为门禁不存在。

## 存档损坏或迁移失败

1. 让用户先导出原始存档，保留现场。
2. 检查 `saveVersion` 是否高于当前客户端；高版本应明确拒绝并提示升级。
3. 检查 checksum 是否匹配；不匹配说明文件被改动或损坏。
4. 用旧版本 fixture 复现迁移；确认迁移幂等且 `assertWorld` 通过。
5. 修复后发布新版本，按 [数据迁移与回滚方案](02-数据迁移与回滚方案.md) 恢复数据。
6. 不得静默重置存档或删除失败记录。

## LLM 代理 / 无 Key

- 无 Key、断网、超时、返回校验失败时，AI GM 必须降级为模板叙事，不阻塞回合推进。
- 检查代理地址与凭据是否通过安全存储配置；不要把 Key 写进仓库或日志。
- Agent 只能返回叙事/受约束提案，不能直接修改游戏事实。

## Android 构建

- 确认 JDK 21、`ANDROID_HOME`、Android SDK 与 Gradle 网络可用。
- 先 `npm run android:sync` 再 `./gradlew assembleDebug`。
- 调试包未签名；正式签名、版本号与隐私声明是人工步骤，未完成时不能发布。
- 返回键与生命周期问题优先检查 `src/platform` 端口实现，而不是在页面里直接调用 Capacitor。

## 密钥扫描误报

1. 确认命中是否是真的凭据；真实凭据必须移除并轮换，不能只加排除。
2. 误报时先确认模式是否过宽；不放宽全局正则来“消灾”。
3. 构建产物、依赖、覆盖率与 `quality/reports/` 已被排除；锁文件仍会扫描。
4. 无法立即修复时按 [规则例外记录](../08-变更与治理/04-规则例外记录.md) 登记，并在 CHG 说明替代措施。

## 恢复后的收尾

- 记录根因、影响范围、修复提交与验证命令。
- 更新 CHG 的“验证证据”“兼容与回滚”与“技术债与例外”。
- 若暴露流程缺口，在技术债或规则例外中登记，而不是只口头说明。
