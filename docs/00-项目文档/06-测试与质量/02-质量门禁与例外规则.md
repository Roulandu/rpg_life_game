# 质量门禁与例外规则

门禁的目标是阻止**已知会破坏项目的行为**，不是制造仪式。所有必需检查都由脚本执行并返回真实退出码；不存在“永远通过”的占位门禁。

## 统一入口

```bash
npm run verify -- --fast   # 快速门禁
npm run verify -- --full   # 全量门禁（默认，CI 同款）
npm run verify -- --list   # 只列步骤
npm run verify -- --help
```

`--base <ref>` 用于需要比较范围的检查；ref 不可达时直接失败，不允许退化成空范围。

## 检查矩阵

| 步骤 | 命令 | 范围 | fast | full | 失败处理 |
|---|---|---|---|---|---|
| 类型 | `npm run typecheck` | 全仓 TS | ✓ | ✓ | 修类型，不用 `any` 掩盖 |
| Lint | `npm run lint` | `src tests scripts` | ✓ | ✓ | 修代码或按规则说明豁免 |
| 数据 | `npm run validate:data` | `data/` | ✓ | ✓ | 修数据；不得跳过校验 |
| 文档生成一致性 | `npm run docs:check` | `docs/modules.yaml` → 生成文件 | ✓ | ✓ | 运行 `npm run docs:build` 并提交结果 |
| 技术债 | `npm run quality:tech-debt` | 阈值 + 基线 | ✓ | ✓ | 拆分代码；不得抬高基线 |
| 模块边界 | `npm run quality:boundaries` | import 图 | ✓ | ✓ | 走公共入口或登记依赖决策 |
| 变更记录 | `npm run quality:change-records` | CHG/VER | ✓ | ✓ | 补记录或修状态/章节 |
| 全仓密钥 | `npm run quality:secrets` | `git ls-files` | ✓ | ✓ | 移除密钥；不放宽正则 |
| 重复率 | `npm run quality:duplication` | 全仓 | | ✓ | 抽取公共逻辑 |
| 测试影响 | `npm run quality:test-impact -- --base <ref>` | 变更源码 ↔ 测试 | | ✓ | 补测试；`Test-Impact` 例外需理由 |
| 文档同步 | `npm run quality:doc-sync -- --base <ref>` | 源码 ↔ 文档/契约 | | ✓ | 更新文档或 `Docs-Impact` 豁免 |
| 覆盖率 | `npm run test:coverage` + `npm run quality:coverage` | 全局与模块 | | ✓ | 补测试；不得下调基线 |
| 防回归 | `npm run quality:anti-regression -- --base <ref>` | 测试数量、存档版本、引擎确定性 | | ✓ | 修行为或按规范升级版本/golden |
| 基线完整 | `npm run quality:baseline` | 基线文件一致性 | | ✓ | 只允许 `quality:update` 降基线 |
| 提交范围 | `npm run quality:commit-range -- --base <ref>` | `base..HEAD` 提交信息 | | ✓ | 新提交修正；不改写已推送历史 |
| 构建 | `npm run build` | Vite 产物 | | ✓ | 修构建错误 |

Git hooks 额外执行：

| 钩子 | 命令 | 作用 |
|---|---|---|
| `commit-msg` | `npm run quality:commit-msg` | 六段模板、Trailer、CHG 关联 |
| `pre-commit` | `npm run quality:staged` | 暂存区路径与快速检查 |

`npm run hooks:doctor` 检查钩子是否真正指向 `.githooks`；钩子未安装时门禁只在 CI/手动运行，不能假设本地已拦截。

## 禁止行为

- 删除或跳过测试，使用 `.only` / 无理由 `.skip` 制造假绿。
- 调高 `quality/*-baseline.json` 或新增 `knownViolations` 来消除告警。
- 未经声明使用 `--no-verify`；CI 会复查 `base..HEAD` 的每个提交。
- 修改断言或 fixture 来掩盖未实现的行为。
- 让脚本在缺少输入时“成功退出”。

## 基线规则

机器事实源是 `quality/*-baseline.json` 与 `npm run quality:report`；基线只能持平或下降。确实需要接受新债务时：

1. 在 [技术债记录](../08-变更与治理/03-技术债记录.md) 登记需要人决策的债务。
2. 在 CHG 的“技术债与例外”说明原因、范围、退出条件。
3. 提交必须带 `Baseline-Update: <说明>`。

## 例外流程

规则例外不是“静默跳过”，而是显式记录：

1. 在 [规则例外记录](../08-变更与治理/04-规则例外记录.md) 新增 `EXC-YYYYMMDD-NNN`，写范围、原因、风险、替代验证、责任人、复查条件。
2. 在对应 CHG 中引用该 EXC。
3. 例外只覆盖声明的范围；不得把“这次例外”扩展成永久规则。

`EXC` 不是自动门禁的一部分；没有脚本会因为存在 EXC 就自动放行。需要放行的检查必须由人工在提交/评审中明确说明。

## 当前未覆盖项

| 项 | 现状 | 风险 |
|---|---|---|
| 设备/视口矩阵 | 仅约定手动 360–390px 与桌面验收 | UI 回归可能漏检 |
| 真机 Android 构建 | 本地手动 Gradle | 签名/上架问题不会在 CI 暴露 |
| 变异测试 | 未引入 | 测试有效性未量化 |
| 端到端浏览器测试 | 未引入 Playwright | 关键流程依赖人工 |
| 远端分支保护 | 仓库文件无法配置 | main 的 CI 仅为可见检查 |

未覆盖项不等于豁免；发布前仍需按 [构建与发布流程](../07-发布与运维/01-构建与发布流程.md) 手工检查。
