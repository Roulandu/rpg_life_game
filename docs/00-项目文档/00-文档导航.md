## 目录结构

```text
docs/
  README.md                                  # 兼容指针，只指向本页
  modules.yaml                               # 模块、依赖、测试、文档、已知违规的唯一事实源
  00-项目文档/
    00-文档导航.md                           # 本文件
    01-项目与需求/                           # 项目概述、产品路线
    02-架构设计/                             # 总体架构、模块边界、生成清单、多端适配、ADR
    03-功能设计/01-功能规则与流程/           # 每个核心功能的业务规则、时序图、测试映射
    04-接口与数据/                           # 引擎接口、Agent 工具、数据模型、数据包、LLM 代理
    05-开发规范/                             # 开发流程、提交、TDD、平台、技术债、文档同步
    06-测试与质量/                           # 回归策略、质量门禁、CI 与交付
    07-发布与运维/                           # 构建发布、迁移回滚、故障恢复
    08-变更与治理/                           # governance.yaml、CHG、VER、技术债、例外、模板
```

`docs/modules.yaml` 与 `docs/00-项目文档/08-变更与治理/governance.yaml` 是机器配置；其余人工文档都在编号树内。

## 文档状态

功能文档 frontmatter 的 `status`：

- `implemented`：代码已存在，文档按当前行为维护。
- `planned`：计划中；`plannedCode` 允许不存在，链接用 `planned:` 前缀，不参与存在性检查。
- `deprecated`：保留作历史参考，代码可能已移除。

## 生成文件

[模块清单-生成](02-架构设计/03-模块清单-生成.md) 由 `docs/modules.yaml` 生成。不要手改；运行：

```bash
npm run docs:build
```

CI 会检查生成文件与结果逐字节一致。

## 维护规则

1. 改行为的提交必须同步改对应功能文档，或写 `Docs-Impact: none: <理由≥4字>`。
2. 新增模块/功能：先注册 `docs/modules.yaml`，再写功能文档，再写代码。
3. 文档路径、frontmatter `code/tests` 路径必须真实存在（`planned` 除外）。
4. 影响模块边界、状态模型、平台策略的决策写 ADR，并链接到相关文档。
5. 文档过期检查：`last_reviewed` 超过 180 天会告警，不阻断；review 时顺手更新。
6. `feat / fix / refactor / perf` 提交必须关联 `变更记录: CHG-...`；记录状态与章节要求见 [治理说明](08-变更与治理/00-治理说明.md)。
