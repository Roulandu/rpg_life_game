## 背景与目标

更新 CHG-20261103-001 状态时，提交信息校验报“Docs-Impact: updated 但修改范围中没有 docs/ 文件”，实际暂存文件是中文路径的 CHG。根因是 Git 默认按 `core.quotePath` 输出八进制转义路径，`stagedFiles()` 把 `"docs/00-\351..."` 当成普通字符串，导致中文文档既不被识别为 `docs/`，也无法参与范围覆盖校验。

目标：所有 Git 路径读取统一返回原始 UTF-8，恢复中文文档与测试路径的真实校验，并加回归测试防止再次漏检。

## 验收条件

- `stagedFiles()` 对中文暂存路径返回原文 `中文文档.md`，不返回转义形式。
- 新增测试在修复前失败、修复后通过。
- 提交信息校验能识别中文 CHG 路径的 `Docs-Impact` 与修改范围覆盖。
- `npm run verify -- --full --base origin/main` 通过。

## 影响范围

- `scripts/quality/lib/git.ts`：统一 Git 读取出口。
- `tests/quality/git.test.ts`：新增中文路径暂存测试。
- 本 CHG 记录；不涉及业务代码、存档结构或用户界面。

## 方案与取舍

在 `lib/git.ts` 唯一的 `run()` 出口添加 `-c core.quotePath=false`，让 `stagedFiles`、`workingFiles`、`diffNames`、`commitsSince` 等全部读取函数统一返回原始路径。相比逐函数加参数，单点修复不会漏掉后续新增调用；也不改变提交信息格式或放宽校验规则。

- `commit-msg` 与 `commit-range` 复用同一 `stagedFiles` / `diff-tree` 路径读取，修复后中文文档范围校验同时生效。
