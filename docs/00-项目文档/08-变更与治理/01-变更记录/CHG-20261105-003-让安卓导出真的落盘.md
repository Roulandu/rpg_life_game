## 背景与目标

真机试玩反馈的问题 1：在 HONOR 真机上点「导出存档」，提示说「存档已导出为 JSON 文件。」，但设备上**找不到任何文件**。

链路核实过，两件事叠在一起才造成这个现象：

- `src/platform/fileExport.ts` 全文只有 12 行，且只有 DOM 一条分支 —— `Blob` + `URL.createObjectURL` + `<a download>` + `click()`。Capacitor 的 WebView 没接 `setDownloadListener`，这个下载请求被**静默丢弃**，不报错、不抛异常。
- `src/store/careerSlice.ts` 的 `exportCurrent` 在调用后**无条件** `set({ notice: '存档已导出为 JSON 文件。' })`。端口没有返回值，调用方无从知道真假。

`@capacitor/filesystem@^8.1.5` 与 `@capacitor/share@^8.0.3` 早已随包安装并在 `android/capacitor.settings.gradle` 注册，工程里也已经声明了 FileProvider —— 也就是说原生导出**只差 import 那一段**，不需要任何 Gradle 或 manifest 改动。`02-架构设计/04-跨平台适配设计.md` 已把这个缺口显式登记为「真机能否落盘属未验收项」。

目标：让原生导出真的产出文件并交给系统分享面板，同时让提示**如实反映端口结论** —— 失败不能报成功，取消不能报失败。

本次不做：不申请任何存储权限，不写公共 `Documents` 目录，不动 `AndroidManifest.xml` / `file_paths.xml`，不动 `save.schema.ts`、`CURRENT_SAVE_VERSION`、`ENGINE_VERSION` 与 golden（本批不改引擎输出）。

## 验收条件

- `exportTextFile(content, filename): Promise<FileExportResult>` 成为唯一的导出端口；`downloadTextFile` 不存在（不留兼容壳）。
- 原生分支：`Filesystem.writeFile({ path, data, directory: Cache, encoding: UTF8 })` 成功后，用返回的 `uri` 调 `Share.share({ files: [uri] })`；写盘失败**不得**打开分享面板。
- 成功返回 `{ ok: true, channel: 'native-share', locationZh }`，`locationZh` 说清「在分享面板里保存或发送」而不是「已导出为文件」。
- 失败返回 `{ ok: false, reason, messageZh }`，三态可分辨：`canceled`（用户在分享面板取消）、`unavailable`（设备没有可接收文件的应用）、`failed`（写盘或分享抛错，`messageZh` 带原始原因）。
- `exportCurrent` 按结论分派：`ok` → `notice = locationZh` 且清 `error`；`canceled` → `notice = messageZh` 且**不记** `error`；`unavailable` / `failed` → `error = messageZh` 且清 `notice`。
- Web 分支行为不变（anchor 下载），且不碰任何 Capacitor 插件。
- `world === null` 时不调用端口。
- 存档文件名组装规则与非法字符替换保持原样；`tests/store/exportSave.test.ts` 的既有两条断言不减少。
- 测试数量不下降，`npm run verify -- --fast` 全绿。

## 方案与取舍

- **`Directory.Cache` + 分享面板，而不是 `Directory.Documents`**：写公共目录在 Android 10 需要 `requestLegacyExternalStorage`、11+ 只能访问 App 自建目录，那是权限面扩张。缓存目录私有、免权限，配合工程里已有的 FileProvider（`android/app/src/main/AndroidManifest.xml` 已声明 `${applicationId}.fileprovider`，`res/xml/file_paths.xml` 已含 `<cache-path path="." />`，正好覆盖 Cache 的 `file://` URI）就能把文件送进系统分享面板，**本批零 Gradle / manifest 改动**。代价写进文档：缓存可能被系统回收，所以成功提示只承诺「在分享面板里保存或发送」。
- **`FileExportResult` 是判别式联合而不是抛异常**：照 `keyStore.saveApiKey` 的既有惯例（返回 `{ persisted, warning? }`）。取消、不可用、失败是三种**需要不同文案**的正常结局，用异常携带业务状态会让调用方 catch 里再做一次字符串判断。
- **计划里的四个 `reason` 收敛为三个**：原设计留了 `denied`（权限被拒）。本批不申请任何权限，`denied` 不可达，留着是死分支，按「不为不可能的场景加处理」删掉。
- **取消的判定用宽容正则 `/cancel/i`**：`Share.share` 的用户取消在各版本上 reject 的具体串不同（`Cancel` / `cancelled` / `Share canceled`），真机串尚未采集。`unavailable` 同理用 `/not available|no activity|unable to share/i`。两条都登记为真机复测项，采集到真实串后可收紧。
- **不留 `downloadTextFile` 兼容壳**：全仓只有 `store/exportSave.ts` 一个调用方，且签名从 `void` 变 `Promise`，留壳等于留一个会静默丢文件的分支。
- **`Share.share` 传 `files: [uri]` 而非 `url`**：`ShareOptions.url` 已废弃且只支持单个分享对象；`files` 是 `file://` URL 数组，Android/iOS 支持，Web 为 no-op —— 而 Web 走的是另一条分支，不受影响。

原因：`vi.fn().mockRejectedValueOnce(Promise.reject(new Error('Cancel')))` 会把**Promise 对象本身**作为 reject 值抛出（探针脚本实测 `CAUGHT: raw<[object Promise]>`），于是 `textOf(error)` 得到 `[object Promise]`。改为 `mockImplementationOnce(() => Promise.reject(new Error(message)))` 后 reject 值才是真实 Error —— 这才是 Capacitor 插件的实际行为。同时 `mockRejectedValueOnce(promise)` 那种「先建好再等被消费」的写法会触发 Vitest 的 Unhandled Rejection 告警。

## 防回归

- `tests/platform/fileExport.test.ts` 的 `回归: 安卓导出仍走浏览器下载分支…` 直接断言 `writeFile` 的入参形状（`path/data/directory:'CACHE'/encoding:'utf8'`）与 `Share.share` 收到 `files:[uri]`。以后谁把原生分支改回 `<a download>`，或者把缓存目录换成别的 `Directory`，这条会立刻失败。
- `回归: 原生写盘失败时提示仍然说「存档已导出为 JSON 文件」` 钉住两件事：`ok === false` 且 `messageZh` 带上原始错误文本，并且**分享面板未被调用** —— 「写盘失败却继续分享」会指向一个不存在的 URI。
- `tests/store/exportNotice.test.ts` 把「提示跟随真实结论」钉在 store 层：失败分支断言 `notice` **不等于**那句假成功，取消分支断言 `error` 为 `null`。这两条是问题 1 的另一半 —— 端口诚实了但提示仍然撒谎，同样算没修。
- `tests/platform/exports.test.ts` 是端口面契约：`exportTextFile` 必须是函数、`FileExportResult` 必须是具名导出的类型。改名或从 `src/platform/index.ts` 撤掉导出面会在这里失败。

## 兼容与回滚

不动存档结构（`CURRENT_SAVE_VERSION` 仍为 12）、不动引擎（`ENGINE_VERSION` 与 golden 哈希不变），旧档与新档都不受影响。`FileExportResult` 只在 `platform → store` 之间流动，不进入任何持久化负载或导出文件。

回滚即回退本提交：`exportTextFile` 恢复为同步 `downloadTextFile`，`exportCurrent` 恢复无条件提示。回滚不会遗留文件 —— 写入的是 App 私有缓存目录，卸载或系统回收即清，公共存储从未被写入。

## 技术债与例外

- `src/platform/fileExport.ts` 66 行、最长函数 35 行，都在阈值内；`shareNativeFile` 与 `downloadInBrowser` 分文件内两段而非新建适配器，避免为一个端口造 `adapters/` 层级（`modules.yaml` 目前是扁平的 `platform/*.ts`）。
- `@capacitor/filesystem` 与 `@capacitor/share` 从「装了但没人 import」变成真实依赖，**未新增任何包**，lockfile 不变；动态 `import()` 让 Web 构建不把插件打进主包。
- 一处测试写法教训已写进「验证证据」：`mockRejectedValueOnce` 传 Promise 会把 Promise 当 reject 值抛出。若以后还要 mock 异步失败，统一用 `mockImplementationOnce(() => Promise.reject(...))`。
