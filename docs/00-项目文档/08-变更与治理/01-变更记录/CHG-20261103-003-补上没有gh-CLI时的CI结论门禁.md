## 背景与目标

上一批交付报告把「没有 gh CLI，CI 结论来自 GitHub Actions REST 轮询，不是 `gh run watch`」列为未闭环项：本机 `where gh` 无结果，而 `AGENTS.md` 与提交规范只写了 gh 一条路径，开发者只能临时手搓 `curl`，既没有可复用的判定口径，也没有门禁退出码。

目标：在仓库内提供 `npm run ci:wait`，用 Node 自带 `fetch` 轮询 Actions REST，给出「排队 / 进行中 / 通过 / 未通过」四态结论与退出码，并把文档改成「默认 `ci:wait`，装了 gh 才用 gh」。本次不做：安装 gh、不改 CI workflow、不引入任何新依赖。

## 验收条件

- 判定逻辑是纯函数，可被测试直接 import；`conclusion: 'failure'` 判为未通过，未 completed 判为进行中，空数组判为排队。
- `npm run ci:wait` 在真实仓库上能取到本次 HEAD 的 run 并打印结论；超时或取不到数据时退出码 1 且输出「CI 未出结果」，绝不默认通过。
- `npm run verify -- --fast` 与 `--full` 通过；`ci:wait` 不进 `check`/`verify` 步骤（要联网）。
- `AGENTS.md`、`docs/00-项目文档/05-开发规范/02-中文提交与变更记录规范.md`、`docs/00-项目文档/06-测试与质量/01-测试与回归策略.md`、`.qoder/skills/feature-delivery/SKILL.md` 口径一致。

## 影响范围

- `scripts/quality/lib/ci.ts`：新增 `resolveVerdict` / `formatVerdict` 纯决策函数与 `ActionsRun` 类型。
- `scripts/quality/check-ci.ts`：新增取数与轮询外壳（`--sha` / `--repo` / `--timeout` / `--interval` / `--json`）。
- `package.json`：新增 `ci:wait` 脚本。
- 测试：`tests/quality/ci.test.ts`（7 例）。
- 文档：AGENTS 常用命令与「推送与 CI 闭环」、提交规范四步闭环、回归策略、feature-delivery skill。
- 不涉及 `src/`、存档结构、游戏数值与用户界面。

## 方案与取舍

拆成「纯决策函数 + 取数外壳」：`resolveVerdict(runs)` 只做四态判定与原因文案，外壳只负责 `git rev-parse`、`git remote get-url` 解析仓库、分页取 `workflow_runs` 和 sleep 轮询。这样判定可被 `tests/quality/ci.test.ts` 直接 import（满足 `quality:test-impact` 的「改动的测试必须直接 import 改动的实现」），联网部分不参与单测。

替代方案是装 gh CLI 或加 `@actions/http-client` 依赖：前者被用户明确否掉，后者违反「新增依赖必须说明理由」，且 Node 24 的全局 `fetch` 已够用。仓库是 public，匿名轮询实测可用，`GITHUB_TOKEN` / `GH_TOKEN` 存在时才带 `Authorization`，避免把凭据写进脚本。

## 验证证据

- `npx vitest run tests/quality/ci.test.ts` — RED：`Cannot find module '../../scripts/quality/lib/ci'`（实现文件尚未创建）。
- `npx vitest run tests/quality/ci.test.ts` — GREEN：`Test Files 1 passed (1)`，`Tests 7 passed (7)`。
- `npm run ci:wait -- --sha 7519fd1f851d...`（历史提交）— 命中 run 41462427671，输出 `CI success`，退出码 0。
- `npm run ci:wait -- --sha <未起跑的新提交>` — 轮询到超时后输出「CI 未出结果」，退出码 1，证明不会默认通过。
- `npm run verify -- --fast` — 通过，8 个步骤，退出码 0（含 `quality:change-records`、`quality:secrets`）。
- 远端 CI：本 CHG 提交推送后由后续文档提交回填 run 链接与 sha。

## 防回归

- `tests/quality/ci.test.ts` 覆盖四态判定、失败 run 明细、run id 汇总与文案输出，任一 run 未 completed 不得判成功。
- 脚本把「取不到 run」和「超时」都归到退出码 1，配合文档「未出结果不得声称完成」，杜绝把网络故障读成绿灯。
- 连续 3 次取数失败即退出，避免配额耗尽时空转 15 分钟。

## 文档影响

更新 `AGENTS.md` 常用命令与「推送与 CI 闭环」、`05-开发规范/02-中文提交与变更记录规范.md` 的失败四步闭环、`06-测试与质量/01-测试与回归策略.md` 的等待口径、`.qoder/skills/feature-delivery/SKILL.md` 的 CI 闭环段：统一成「默认 `npm run ci:wait`，装了 gh 才用 gh，两者都必须等到最终结论」。

## 兼容与回滚

纯新增脚本与文档措辞，不改 CI workflow、不改门禁步骤集合，`check:fast` / `check` 入口保持原语义（由 `verify.ts` 提供）。回滚即删除 `ci:wait` 脚本与两个文件，旧流程退回 gh 单一路径，不影响任何已推送提交。

## 技术债与例外

未新增技术债：两个新脚本文件均在 300 行、60 行、圈复杂度阈值内，新文件重复率低于 5%。未修改 `quality/*-baseline.json`，未新增 `knownViolations`，未放宽任何门禁。

## 验收结论

本地 RED/GREEN 真实可复现，`npm run verify -- --fast` 8 步全绿，两次真实轮询分别证明「通过」与「未起跑 → 退出码 1」两条口径。状态记为 `verified`；推送后由后续文档提交补 sha、CI run 与 `accepted` 结论。
