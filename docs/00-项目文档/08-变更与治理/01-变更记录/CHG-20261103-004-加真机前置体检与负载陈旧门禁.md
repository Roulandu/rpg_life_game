## 背景与目标

交付报告把「未跑真机：UI 的 DoD 与存档红线的设备部分未验收」列为未闭环项。查证后发现根因不只是缺设备：`android/app/build/outputs/apk/debug/app-debug.apk` 停在 2026-10-25 23:01，`android/app/src/main/assets/public/index.html` 停在 10-25 23:10，而 `dist/` 已经在 v11/v12 存档、财务与个人团队之后——即便插上手机装的也是旧界面，而且仓库里没有任何命令会报告这件事。

目标：把「真机验收前必须成立的事实」变成一条可读、可判退出码的门禁 `npm run android:doctor`，用它重建当前 APK，并把真机验收清单与结论口径写进文档。本次不做：真机清单执行（本机 `adb devices` 为空）、`src/platform/fileExport.ts` 的原生导出分支（属新行为改动，另起一批）、发布签名。

## 验收条件

- 判定逻辑是纯函数、可被测试直接 import：设备不在场只提醒，负载不一致或 `dist`/`assets/public` 缺失必须判失败。
- `npm run android:doctor` 在修复前真实报出「WebView 负载陈旧」与「APK 比负载旧」，退出码 1；`npm run android:sync` + `assembleDebug` 后只剩「无在线设备」一条提醒。
- 文档三处口径一致：真机验收清单与结论口径、Android 打包前置体检与陈旧检测、平台矩阵里 Android 与文件导出的真实状态。
- `npm run verify -- --fast` 与 `--full` 通过。

## 影响范围

- `scripts/quality/lib/device.ts`：新增 `DeviceProbe` / `DeviceReport` 类型与 `assessDeviceReport` / `formatDeviceReport` 纯函数。
- `scripts/quality/check-device.ts`：新增探针采集（SDK 环境变量、adb 可用性、`adb devices -l` 在线设备、`dist` 与 `assets/public` 的 index.html SHA-256、debug APK 的字节数与 mtime）与结论打印。
- `package.json`：新增 `android:doctor` 脚本。
- 测试：`tests/quality/device.test.ts`（7 例）。
- 文档：`05-开发规范/04-跨平台开发规范.md`（新增「真机验收」小节、能力矩阵文件导出行改为真实现状、新平台接入清单补体检步骤）、`07-发布与运维/01-构建与发布流程.md`（新增前置体检小节与检查单两条）、`02-架构设计/04-跨平台适配设计.md`（Android 状态由「已支持」收敛为「可构建 · 真机未验收」，补 `fileExport.ts` 原生分支缺口）。
- 不改 `src/`、不改存档结构与游戏数值；`android/` 原生工程文件无改动（`assets/public/` 与 `build/` 都在 gitignore 内）。

## 方案与取舍

沿用 `ci:wait` 的拆法：判定放纯函数、采集放外壳，这样 `tests/quality/device.test.ts` 能直接 import 被测实现（满足 `quality:test-impact`），adb 与文件系统不进单测。

负载陈旧用「两份 `index.html` 的 SHA-256 比对」而不是 mtime：Vite 把资源哈希写进 `index.html`，内容比对能准确区分「重新构建过」与「只是文件被 touch 过」，mtime 只用来判断 APK 是否早于负载。

替代方案是把体检塞进 `verify --full`：被否掉，因为它依赖本机 SDK、adb 与设备在场，CI runner 与开发者机器条件不同，硬塞只会制造假红灯；体检保留为手动门禁。

## 防回归

- `tests/quality/device.test.ts` 两个顶层 describe 分别锁住「就绪判定」（全绿、无设备只提醒、负载不一致判失败、缺 dist/缺 assets 的命令提示）与「工具链与产物判定」（ANDROID_HOME 缺失、adb 不可用、APK 陈旧、无 APK），失败项必须出现在 `formatDeviceReport` 文案里。
- adb 解析只认 `state=device`，`unauthorized`/`offline` 不算在线设备，避免把「插着但没授权」读成可验收。
- 文档把「设备不在场只能记未验收」写成结论口径，防止下次再用「应该没问题」顶替真机结论。
