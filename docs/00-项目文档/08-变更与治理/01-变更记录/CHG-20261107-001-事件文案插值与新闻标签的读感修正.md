## 背景与目标

2026-11-06 的三赛季真机实测（问题清单第 10–15 条）里，批次 3 这六条都属于「玩家读到了引擎的内部词汇」：

1. **`{teammate}` 字面量漏进按钮**：`data/events/media.json:32` 的 `md_post_match_mic` 把「让{teammate}去接受提问。」直接画在选项描述上。根因是 `renderEventDraft` 只对 `body` 做插值，`title` 与 `choices[].label/description` 原样返回（`src/engine/data/eventTemplates.ts:77-82`）。
2. **内容门禁看不见同一个坑**：`assertWhitelist` 只扫 `body` 里的占位符（`src/domain/eventContent.ts:154-159`），所以选项、标题、结果文案里写错 token 既不报错也不被替换；而且它的正则 `\{[a-zA-Z]+\}` 抓不到 `{first_name}` 这类带下划线的写法。
3. **事件新闻一律挂「媒体」**：`events.ts:36` 与 `eventsDaily.ts:68` 写死 `kind: 'media'`，教练谈话、队友邀约、家人来信在收件箱里全被打成媒体标签。功能文档从头到尾没规定过事件新闻该挂什么标签（`03-每日事件.md` 的接口表里根本没有 `kind`），所以这条既是实现缺陷也是契约缺口。
4. **平静日说谎**：`TodaySection.tsx:53` 在没有事件时显示「平静日」。实测第 2 赛季后半程球队连败，标题写平静日、下面写球队输了——两个口径互相打脸；比赛日也不该出现这个 chip（那天根本没有什么「平静」可言）。
5. **时间线替后续版本打广告**：`TimelineScreen.tsx:127` 那句「转会与更多奖项会在后续版本加入时间线」把路线图写进了玩家界面，且从未兑现。
6. **团队页把拉丁原名当主信息**：`StaffRows.tsx:56` 在职成员第二行直接放 `member.name`（`Marcus Reid`），没有标注是「原名」，玩家不知道这行是什么。
7. **账本只有类目没有周次**：`FinanceScreen.tsx:14-22` 渲染 `entry.label` 却不带 `第 N 周`，`LEDGER_KEEP = 12` 的历史跨周后看不出发生时间；`key` 用 `season:week:label`，同周同类目（例如一周里两笔「工资」）会撞 key。

目标：让玩家看得见的所有文字要么是真值、要么明确标为原名；新闻标签与事件来源一致；不再用「平静日」这种会打脸的判断句。

## 验收条件

1. 事件 `title`、`choices[].label`、`choices[].description`、`resultTexts` 全部走同一套插值；`md_post_match_mic` 的选项描述渲染成队友中文名，界面里不出现 `{teammate}` 字面量。
2. `assertWhitelist` 的占位符扫描覆盖 title / body / choices / resultTexts，正则能抓带数字与下划线的 token；数据包里写错 token 会在 `npm run validate:data` 阶段抛中文错误。
3. 事件新闻的 `kind` 由 `sender` 决定：教练/队医/体能教练/董事会/体育总监/装备管理员/俱乐部职员/队内厨师/心理咨询师/私教/营养师等俱乐部岗位 → `club`，队友/青训旧友/名宿等更衣室与前辈 → `teammate`，家人/邻居 → `family`，银行/赞助商/房东/经纪人/俱乐部财务/保险公司 → `finance`，媒体与球迷角色 → `media`，自己/联赛官方与未登记角色 → `system`；收件箱与主页 feed 的 chip 能显示这些新档位的中文。
4. 主页「今天」右上角在没有待处理事件时显示「无待处理」，比赛日整个 chip 不渲染（不再出现「平静日」判词）。
5. 时间线不再出现「后续版本加入」这类路线图承诺。
6. 团队页在职成员的第二行明确标注为原名，玩家不会把拉丁串当成另一个名字。
7. 账本每行渲染 `第 N 周 · 类目`，且同一周同一类目出现两笔时 React key 不重复。
8. 全量测试不减、`npm run verify -- --fast` 与提交后的 `--full --base <推送前 SHA>` 绿；确定性不受影响时 golden 不动，若动则升 `ENGINE_VERSION` 并说明。

## 方案与取舍

**插值放渲染器而不是放数据包。** 数据包里已经写了 96 条模板，把 `{teammate}` 手工换成某个名字等于放弃随机化；渲染器多插两个字段没有新的失败模式，只是把「凡是玩家会读到的文本」定义为同一条流水线。

**新闻 kind 按 `sender` 推导，不给 96 条模板各加一个 category 字段。** 加字段要动 schema、迁移与全部数据包；`sender` 已经是每条必填的中文角色名，映射表 31 行覆盖现有全部角色，没登记过的落到 `system`（不再冒充媒体），并由 `tests/engine/eventDaily.test.ts` 盯住「映射表至少分出五个档位」。这条口径第一次写进 `03-每日事件.md`。

**枚举只放宽不重命名。** 旧存档里的 `'media'` 等值继续合法，因此不升 `CURRENT_SAVE_VERSION`；反过来把 `media` 拆成多个旧值会让历史新闻无法读回，坚决不做。

**「平静日」换成「无待处理」是口径收敛而不是美化。** 前者是对一天生活的评价，后者只描述「有没有要玩家处理的事」，与下面的比赛结果、财务状况不再互相打脸。

## 技术债与例外

- 历史新闻里被写成 `media` 的家人/队友/财务事件不做回溯修复：只在读档后新产生的事件上使用新档位。旧档新闻的标签与今天读起来不一致，是可接受的近似，不登记为待办。
