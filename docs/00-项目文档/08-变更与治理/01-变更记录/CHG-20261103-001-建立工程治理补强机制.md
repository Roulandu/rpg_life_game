## 背景与目标

项目已有模块清单、质量脚本、Git hooks 与单条 CI，但缺少可追踪的变更/验证记录、无 PR 也能运行的门禁、统一验证入口、全仓密钥扫描和发布/回滚文档；文档仍为英文扁平目录，且 `resolveBase` 在 base 不可达时会静默退化为空范围。

目标：在不重写业务代码的前提下，把规则、流程、脚本、CI 与变更记录做成可运行的闭环，并如实标明远端强制范围与未覆盖项。

## 验收条件

- 文档全量迁移到中文编号目录，旧路径有对照表，链接与生成器同步。
- `governance.yaml` + CHG/VER 校验脚本可运行；四类提交必须关联存在的 CHG。
- `npm run verify -- --fast|--full|--help|--list` 可运行并写机器可读报告，失败也写报告。
- CI 覆盖所有分支 push、`v*` 标签、PR、手动触发与每周定时；base 不可达直接失败。
- 模块清单包含职责与契约；全仓密钥扫描可运行。
- 发布、迁移回滚、故障恢复文档存在且与脚本/命令一致。
- 不自动提交、推送、打 tag 或部署；未运行的 CI 不得写成已通过。

## 影响范围

- `docs/`：编号迁移、导航、治理配置、CHG/VER、质量/发布/故障文档、模块清单生成文件。
- `scripts/quality/`：`lib/git.ts`、`lib/commit.ts`、`lib/governance.ts`、`lib/secrets.ts`、`check-change-records.ts`、`check-secrets.ts`、`check-doc-sync.ts`、`generate-module-docs.ts`、`inspect-file.ts`、`install-hooks.ts`。
- `scripts/verify.ts`、`package.json`、`.github/workflows/ci.yml`、`.gitignore`、`.gitattributes`。
- `tests/quality/`：git、commit、governance、verify、secrets 测试。
- `AGENTS.md`、`.qoder/skills/feature-delivery/SKILL.md`、`docs/modules.yaml`。

## 方案与取舍

- 采用编号文档树，保留 `docs/README.md` 作为兼容指针；`modules.yaml` 与 `governance.yaml` 保持机器配置位置。
- CHG 使用 `draft → verified → accepted → superseded`，`verified` 只要求本地必需检查完成，`accepted` 才要求 CI run，避免每次变更写两份记录。
- 统一验证入口复用现有 npm 子脚本，避免规则漂移；报告记录 SHA、dirty、base、Node/npm 与每步结果。
- base 解析改为显式校验；不可达、无共同祖先或 `rev-list` 失败都抛错，不输出假绿。
- 全仓密钥扫描复用 `lib/secrets.ts`，只排除依赖/构建/覆盖率/报告目录与二进制/超大文件，锁文件仍扫描。
- 不新增依赖，不做自动部署、设备矩阵或变异测试。
