# 防回归

## 目标

防止“修好 A，弄坏 B”，尤其是多人/多轮修改同一文件时。防回归不是靠记忆，而是靠：

1. 修改前先看上下文。
2. bug fix 先复现。
3. 关键不变量有自动测试。
4. 提交里写清回归风险和验证。
5. CI 永远跑全量。

## 修改同一文件前

跑：

```bash
npm run quality:file -- src/engine/match.ts
```

输出包含：

- 所属模块、相关功能文档。
- 映射测试与最近 5 次触及该文件的提交。
- 当前指标与基线。
- 该模块的回归清单。

然后按顺序：

1. 读功能文档和映射测试。
2. 跑该模块最小测试集。
3. 看最近提交，理解上次为什么改。
4. 确认本次修改触及的不变量。
5. 写测试/回归用例。
6. 改代码。
7. 跑全量。

## 关键不变量

| 领域 | 不变量 |
|---|---|
| 引擎确定性 | 同 seed、同输入 → 同输出；禁止墙钟/未播种随机 |
| 原子回合 | 一次推进的所有状态变更一起提交，避免半更新存档 |
| 存档 | envelope、校验、版本、迁移、导出/导入往返 |
| LLM 降级 | 无 Key/断网/超时/校验失败必须回退模板，不阻塞推进 |
| Agent 边界 | LLM 只返回提案/叙事，不直接改事实 |
| 模块边界 | 新增依赖必须符合 `docs/modules.yaml` |
| 平台 | 核心域不直接使用 Capacitor/DOM/微信 API |
| UI | 关键流程在手机宽度可用，触控/输入尺寸达标 |

## Bug fix 政策

1. 先写能复现 bug 的测试，确认失败（RED）。
2. 测试名用 `回归: <现象>`。
3. 修复，确认同一个测试通过（GREEN）。
4. 提交 `回归风险与验证` 写清同类问题是否还存在。
5. 不允许“只改代码，测试后补”。

如果无法写自动测试，必须写清手动复现步骤、环境、视口，并在提交里说明为什么无法自动化。

## Golden replay

`tests/engine/golden.test.ts`：

- 固定 seed 42 + 固定策略，模拟完整赛季。
- 对规范化 `WorldState` 做哈希，与 `quality/golden/season-seed-42.json` 比对。
- 任何引擎输出变化都会改变哈希，这是有意的。

引擎行为变化时：

1. 确认变化符合需求。
2. 更新 `ENGINE_VERSION`。
3. 更新 golden 哈希。
4. 在提交里解释“为什么输出必须变”。
5. 更新功能文档/变更记录。

不要为了过测试直接改哈希而不解释。

## 存档迁移

改 `src/domain/schema/save.schema.ts` 或 `CURRENT_SAVE_VERSION` 时：

- 升版本号。
- 提供从旧版本到新版本的迁移。
- 保留旧版本 fixture。
- 加导出/导入往返测试（深度相等）。
- 文档更新 `docs/data-model.md` 的迁移表。
- 提交说明兼容性：旧档能否继续、是否需要提示用户。

`check-anti-regression` 检测到 schema 文件变化但版本号未变时失败。

## 确定性

`tests/engine/determinism.test.ts` 扫描 `src/engine`、`src/world`，禁止：

- `Math.random`
- `Date.now`
- `new Date()`
- `performance.now`

新增随机性必须通过 `createRng(world.seed, domain, ...)`，并保证同种子可重放。

## 测试数量与跳过

- 改动测试文件的用例数不得减少，除非 `Test-Impact: removed: <理由>`。
- 禁止 `.only`。
- `.skip` 必须同行写 `skip-reason: <原因>`；无理由 skip 视为删除测试。
- 不允许改 fixture/断言来掩盖行为变化。

## CI 全量

- 本地可以只跑相关测试提高速度。
- push/PR 必须跑全量：typecheck、lint、data、全量测试、覆盖率、build、所有门禁。
- CI 不做路径过滤，不把“只跑改动测试”当作唯一验证。
- CI 复查 `base..HEAD` 的提交信息，`--no-verify` 绕不过去。

## 提交里的回归说明

`回归风险与验证` 至少包含：

- 风险：可能影响的行为/数据/平台。
- 验证：具体测试/命令/手动步骤。

示例：

```text
回归风险与验证:
- 风险：跳过关键时刻的结算路径与观看路径分叉
- 验证：tests/engine/keyMoments.test.ts 新增观看/跳过对比用例；tests/engine/season.test.ts 全量赛季通过
```

## 常见回归模式

| 模式 | 预防 |
|---|---|
| 改了共享函数，另一个调用方行为变了 | 先搜所有调用方，加测试 |
| 改了存档字段，旧档读不出 | 版本 + 迁移 + 旧 fixture |
| 改了 RNG 调用顺序，回放全变 | golden replay + 提交解释 |
| 改了 UI 状态流，刷新后丢失 | store/存档往返测试 + 手动刷新 |
| 改了 Agent 输出，校验失败导致卡住 | 失败降级测试 + 模板回退 |
| 改了平台判断，Web 正常但 Android 崩 | 平台能力矩阵 + 端口契约测试 |
| 删/改了测试让 CI 变绿 | 测试数量棘轮 + review |

## Review 清单

- [ ] bug fix 有复现测试。
- [ ] 同一文件的历史风险已检查。
- [ ] 关键不变量有覆盖。
- [ ] 全量测试通过。
- [ ] 存档/引擎变更解释了兼容性。
- [ ] 提交的回归说明具体、可执行。
- [ ] 没有删除/跳过测试来过关。
